# Введение

Проект численно исследует трехмерную систему двухфазного гидродинамического 
движения (условные обозначения переменных `q1`, `q2`, `r`). 
Для сетки начальных точек программа решает систему вперёд и назад во времени 
методом RK45 и относит каждую точку кодному из шести классов.
Условные названия классов `red`, `green`, `blue`, `black`, `white_0`, `white_1`.
Если класс определить не удалось, точку относят к типу `smth`.

## Структура каталога проекта

```text
/sisoflow
├── main_test_rk45.py       Основной файл (расчёт сетки, интегрирование и классификация)
├── params.yaml             Конфигурационный файл (решаемая система уравнений,
│                           значения параметов модели, параметры решателя, настройки визуализации)
├── 00_pusk.sh              Файл запуска PBS-задачи
├── 01_run.sh               Файл запуска расчёта через mpirun
├── 02_proc.sh              Постобработка результатов расчетов
├── README.md               Настоящее описание
├── plotters/
│   └── phase_space.py      Код визуализации результатов классификации
└── tests/
    └── test_fixed.py       Проверки сетки, распределения MPI и правой части
```

Результаты расчёта сохраняются в каталоге `saveto`, заданном в
`params.yaml`. По умолчанию используется `./res` относительно рабочего
каталога.

## Математическая модель

Интегрируемая численно система уравнений задается в конфигурационном файле.
Без ограничения общности может быть задана любая трехмерная система.
В реализованном примере решается трехмерная система уравнений
```text
dq1/dt = q1 * (2*a^2*tau*q2 - mu*(q1-q2)*q1*r)
dq2/dt = (q1-q2)*r*(q1^2-a^2)
dr/dt  = tau*q2*r*(q1^2-a^2)
```
q1, q2, r - искомые функции, a, tau, mu - числовые параметры.

В [main_test_rk45.py](main_test_rk45.py) правая часть реализована в функции
`hydro`. Аналитический якобиан доступен в `hydroj`.

Классификация решений строится на основе заданных признаков: 
асимптотическое поведение решений на бесконечности при интегрировании в прямом и обратном направлениях,
выделенных событий. Анализ результатов численного интегрирования системы уравнений 
при различных начальных условиях с целью классификации решений производится
функцией `classify` после интегрирования в обоих направлениях.

В реализованном примере при численном интегрировании системы уравнений для классификации решений
отслеживаются следующие события
1. пересечение траекторией поверхностей `q1 = a` и `q2 = a` в обоих направлениях,
2. пересечение траекторией поверхности `q2 = 0`, 
3. достижение траекторией условной бесконечности по параметру `r` `r = r_inf` при росте `r`.
События `q2 = 0` и `r = r_inf` останавливают интегрирование; пересечения
`q1 = a` и `q2 = a` сами по себе его не останавливают. 

### Критерии классификации

Критерии классификации задаются в процедуре `classify`.

В рассматриваемом примере классификатор учитывает начальные значения `q1`, `q2`, а также
конечные состояния траекторий при интегрировании вперёд (`plus`) и назад (`minus`). 
Проверяются следующие условия:
- Если в начальной точке `q1 <= a` и `q2 >= a`, точка сразу относится к `red`.
- Если `q1 >= a` и `q2 >= a`, класс `green` назначается, когда при
  интегрировании назад зарегистрированы события `q2 = 0` и `q2_ma`
  (пересечение `q2 = a` с направлением события `-1`). Если условие для
  `green` не выполнено, но зарегистрировано событие `q1_ma` (пересечение
  `q1 = a` с направлением `-1`), класс — `red`; иначе — `smth`.
- Для остальных начальных точек сначала проверяется условие белых классов,
  затем применяются критерии по конечным состояниям и событиям:
  - При `q1 >= a`: конечное при интегрировании вперёд `q1 <= a` даёт
    `black`; иначе конечное при интегрировании назад `q1 <= a` даёт `red`;
    иначе событие `q2 = 0` назад даёт `green`. Если ни одно условие не
    выполнено, класс — `smth`.
  - При `q1 < a`: конечное вперёд `q1 > a` или `q2 > a` даёт `red`;
    иначе конечное назад `q1 > a` даёт `black`; иначе сочетание события
    `q2 = 0` вперёд и конечного назад `q1 < delta_blue * q1_начальное`
    даёт `blue`. В остальных случаях класс — `smth`.

Белые классы проверяются по конечной точке прямого интегрирования. Для неё
вычисляется расстояние в координатах `q1`, `r` до кривой
```text
r = 2*a*tau*q2 / (mu*(a - q2))
```

Точка считается лежащей около кривой, если расстояние меньше `eps_w`, а значение
`q2` находится в интервале
`[a/2*(1-sqrt(1-8/mu)), a/2*(1+sqrt(1-8/mu))]` (при `mu > 8`). При `mu <= 8`
код не ограничивает `q2` этим интервалом. Если оба условия выполнены,
наличие события `q2 = 0` назад разделяет классы: оно даёт `white_0`, его
отсутствие — `white_1`.

На результат классификации влияют параметры модели `a`, `mu`, `tau`,
порог белой окрестности `eps_w`, порог синего класса `delta_blue`, предел
радиальной переменной `infty` и временные границы `glob_left`/`glob_right`.
Например, в конфигурации по умолчанию `eps_w = 0.01`,
`delta_blue = 0.01`, `infty = 1000`, `glob_left = -20` и
`glob_right = 1000`.

## Конфигурационный файл

Изменяемые параметры задачи описаны в конфигурационном файле params.yaml

- `const` — параметры системы уравнений `mu`, `tau`, `a`;
- `glob_left`, `glob_right` — границы времени интегрирования назад и вперёд;
- `n_u`, `n_v`, `n_r` — размеры сетки по `q1`, `q2`, `r`;
- `L_u0`/`L_u1`, `L_v0`/`L_v1`, `L_r0`/`L_r1` — границы сетки;
- `logu`, `logv`, `logr` — режим построения осей:
  `1` означает логарифмическую сетку по основанию 10, `0` — линейную;
- `zero`, `infty` — пороги нуля и бесконечности;
- `eps_w` — радиус окрестности особой линии;
- `delta_blue` — порог признака класса `blue`;
- `saveto` — каталог файлов с результатами.

При `logr: 10` значения `r` строятся относительно кривой особых точек.

## Запуск вычислений на одном потоке (локально)

Перейдите в каталог `sisoflow/`, проверьте настройки `params.yaml` и запустите
однопроцессный расчёт:

```bash
cd fixed
python3 main_test_rk45.py --config params.yaml --rank 0 --size 1
```

Аргументы `--rank` и `--size` необязательны. Если они не указаны, программа
берёт номер ранга и размер сообщества из переменных OpenMPI
`OMPI_COMM_WORLD_RANK` и `OMPI_COMM_WORLD_SIZE`; локальные значения по
умолчанию равны `0` и `1`.

Для расчёта с явным числом процессов выполните:

```bash
python3 main_test_rk45.py --config params.yaml --rank 0 --size 4
python3 main_test_rk45.py --config params.yaml --rank 1 --size 4
python3 main_test_rk45.py --config params.yaml --rank 2 --size 4
python3 main_test_rk45.py --config params.yaml --rank 3 --size 4
```

Практический запуск через MPI:

```bash
mpirun -n 4 python3 main_test_rk45.py --config params.yaml
```

Каждый ранг обрабатывает непересекающийся интервал общего индекса сетки начальных точек.
Это обеспечивает обработку каждой точки ровно одним процессом.

## Запуск PBS/OpenMPI на кластере

Из каталога проекта отправьте задачу на PBS-кластер:

```bash
cd fixed
./00_pusk.sh
```

Скрипт отправляет на выполнение [01_run.sh](01_run.sh). PBS-настройки можно
изменить в `01_run.sh`: имя задачи, число узлов и процессов на узле,
очередь и ограничение времени.

По умолчанию скрипт запускается с Python из переменной `PYTHON_BIN` или
системой `python3`:

```bash
PYTHON_BIN=/usr/bin/python3 ./00_pusk.sh
```

Перед запуском проверьте права на выполнение скриптов:

```bash
chmod +x 00_pusk.sh 01_run.sh 02_proc.sh
```

## Результаты расчёта

Для каждого ранга программа создаёт:

- `q1q2r_<класс>_<rank>.txt` — начальные точки класса в текстовом формате;
- `q1q2r_<rank>.pkl` — словарь с начальными точками `init`, конечными
  точками вперёд `pend` и конечными точками назад `mend`.

Номер ранга в именах записывается с ведущими нулями, например `001`.

Для объединения текстовых таблиц выполните:

```bash
./02_proc.sh ./res
```

Для каждого класса будет создан объединённый файл
`res/q1q2r_<класс>.dat`. Скрипт принимает каталог результатов как первый
аргумент и создаёт его при отсутствии.

## Визуализация результатов расчетов

Для каждого фиксированного значения `r` из сетки в плоскости `q1`–`q2`
строится визуализация: цветовая карта разбиения начальных точек по классам.
Команда для запуска процедуры построения изображений выглядит следующим образом
```bash
python3 plotters/phase_space.py \
  --config params.yaml \
  --results ./res \
  --output ./frames \
  --plane q1q2
```
Цветовую карту разбиения по классам можно строить также в плоскости `q1`–`r`.
Эта опция задаётся параметром `--plane q1r`.

Программа читает все `q1q2r_*.pkl` из каталога результатов и сохраняет в
выходном каталоге набор PNG-файлов:

- `q1q2_0000.png`, `q1q2_0001.png`, ... для фиксированных значений `r`;
- `q1r_0000.png`, `q1r_0001.png`, ... для фиксированных значений `q2`.

Matplotlib в этой версии настроен на неблокирующий backend `Agg`, поэтому
визуализацию можно запускать без графического интерфейса.

## Типичный рабочий цикл

1. Определить параметры модели и сетки в `params.yaml`.
2. Настроить число узлов и процессов в `01_run.sh` для параллельного счёта.
3. Запустить локально через `python3` или отправить задачу на кластер через `00_pusk.sh`.
4. Проверить появление `.txt` и `.pkl` файлов в каталоге `res`.
5. Объединить текстовые таблицы командой `02_proc.sh ./res`.
6. Построить цветовые карты через `plotters/phase_space.py`.
7. При необходимости проверить расчёт отдельными unit-тестами.
